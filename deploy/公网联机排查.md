# 转交部署方：公网房间和实时推送排查

游戏不限制局域网地址。同一Node房间服务可以让通过公网域名访问的玩家加入。但前端静态文件本身不提供联机，必须运行项目根目录的 `node server.mjs` 并代理API。

## 已确认的代码问题

旧前端使用绝对路径 `/api/rooms/...`，部署到 `/lx/` 时仍访问网站根目录API，可能命中别的程序或404。当前修复改为相对部署模块所在目录解析，因此 `/lx/` 前端请求 `/lx/api/rooms/...`，根目录部署仍请求 `/api/rooms/...`。列表、创建、加入、准备、同步、离开和推送全部使用同一规则。需要部署修改后的JS与压缩副本并强制刷新所有玩家页面。

对应Nginx示例见 `nginx-subpath.conf.example`。原有域名、TLS配置由部署方保留，先 `nginx -t` 再重载。不要把API转发到静态站点、SPA首页或另一个应用。

## 按顺序检查

1. 所有玩家使用完全相同的游戏URL。电脑本机的127.0.0.1服务、办公室局域网服务与云服务器是独立房间列表，不会自动互通。
2. 浏览器开发者工具Network查看“创建房间”和“刷新列表”的实际请求。若游戏在 `/lx/`，请求应为同域 `/lx/api/rooms/create` 和 `/lx/api/rooms/list`，方法POST、响应Content-Type包含application/json。返回HTML或404就是代理/部署问题。不要发送登录信息或Authorization截图给他人。
3. 一人创建房间后，另一人点击刷新列表；列表不是全局自动实时刷新的。也可以使用创建后返回的六位房间号加入。用两台电脑各发POST `{}` 到同一列表接口比较结果。
4. 在Node上游直接请求 `POST http://127.0.0.1:4173/api/rooms/list`，再比较公网接口。如果上游有房间而公网没有，检查API代理、缓存、服务端口是否一致。API应Cache-Control:no-store；不要缓存API，包括CDN规则。
5. 当前NetworkRooms使用进程内Map。必须让所有API请求命中同一个持续运行的Node实例。PM2 cluster、多容器、多副本、多个upstream、Serverless每次起不同实例都会分裂房间。先使用单实例/fork模式验证；仅做客户端粘性会话也不够，不同玩家仍可能落到不同进程。跨实例共享房间和事件总线尚未实现。
6. 房主离开或20秒无有效心跳会关闭房间；Node重启也会清空所有房间。检查是否反复重启、OOM、进程守护崩溃重启或后台页面冻结。不要通过永久保活旧身份掩盖问题。
7. 加入后检查 `/lx/api/rooms/房间号/events` 长连接：应HTTP200、Content-Type:application/x-ndjson，持续收到状态及空行心跳。必须关闭Nginx/CDN响应缓冲；不能等连接结束才返回。Authorization请求头须正常传到Node。推送失败会退回轮询，但操作延迟会变差。
8. 保留原Host请求头，避免Node的同源检查把浏览器Origin与内部127.0.0.1 Host判成跨站。不要通过删除同源验证或开放任意跨域来绕过代理错误。

## 验证新版对战

同步部署前端和 `network-server.mjs`，重启 Node 后让所有人刷新页面并重开房。房间 API 返回 `fastSync: 1` 表示服务已启用并行上传。旧版服务仍可接新版浏览器的单请求同步，但会保留原来的请求排队行为。

- 客人本机应立即看到跑、停、转向、蹲行、防御姿态和普通攻击起手。短按跳跃在松键时起跳，长按达到阈值后起跳，普通腾空后可本地转向。走路撞墙时应停在墙前，移动不能穿过墙或在悬空地图外继续走。
- 房主仍判定伤害、命中、击退、特殊位移、道具和比分。包重发不应重复攻击。相同动作先在客人看到起手，再在两侧看到一次命中或受击；对比结果时以两侧最终血量一致为准。
- 验证追砍时，让一名客人用剑追击持续移动的目标。房主会对地面剑招的兵器接触按客人画面时刻回查，最多 250 毫秒。隔墙、瞬移前的位置和已失效的旧画面不会获得补偿。防御、扣血和受击仍按当前战斗状态结算。
- 比分区显示中继往返时间、实时推送或轮询，以及客人的显示缓冲。中继往返是自己与 Node 的 HTTP 往返，不能代替按键到房主判定或按键到本机首帧的延迟。节点间抖动变大时，远端角色缓冲会自动增加；连续稳定后回落。
- 可用两台电脑分别从同一局域网和公网域名测试。公网用同一访问 URL 建房、刷新列表、入房，开局后两边都走跑、急停、跳跃、短连击，同时观察房间是否误断开及远端动作是否连续。若长期显示轮询，先排查代理缓冲和推送断流。

地面移动采用客户端记录输入、房主状态为基线回放、显示平滑纠偏的方式。其他玩家、投射物和命中特效共享房主时间轴。当前战斗模拟仍由房主浏览器执行，云端 Node 负责房间与中继。房主设备卡顿、页面挂起和云端代理拥塞仍会影响所有玩家，应分别看房主帧时间、中继往返和推送状态。
